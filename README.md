Customer Shopping Behavior
Analytics Project Report
End-to-end pipeline: CSV → Python cleaning → PostgreSQL → SQL analysis → Power BI dashboard
Report Version 1.0
 
1. Executive Summary
This report documents an end-to-end analytics project built on a customer shopping transaction dataset. Raw data was cleaned and enriched in Python, loaded into a PostgreSQL database, analyzed using a defined set of SQL business questions, and visualized through an interactive Power BI dashboard. The project answers core questions about revenue drivers, customer segments, product performance, and the impact of discounts, subscriptions, and shipping choices on spending behavior.
2. Objective
The project delivers a repeatable pipeline and a self-service dashboard that:
●	Cleans and standardizes raw shopping transaction data.
●	Persists the cleaned data in a relational database (PostgreSQL) for querying.
●	Answers a defined set of business questions using SQL.
●	Presents key metrics and trends visually through a Power BI report.

4. Data Pipeline & Architecture
CSV → Python/Jupyter cleaning & feature engineering → PostgreSQL (customer_behavior database, customer table) → SQL analysis → Power BI dashboard.
4.1 Data Cleaning & Feature Engineering (Notebook)
1.	Load CSV into a pandas DataFrame.
2.	Inspect structure (.head(), .info(), .describe()).
3.	Identify missing values (.isnull().sum()).
4.	Impute missing Review Rating values using the median rating within each category.
5.	Standardize column names to lowercase with underscores.
6.	Rename purchase_amount_(usd) to purchage_amount.
7.	Engineer age_group (quartile split into 4 labeled buckets).
8.	Engineer purchase_frequency_days from the categorical purchase-frequency field.
9.	Sanity-check the relationship between discount_applied and promo_code_used.
10.	Load the cleaned DataFrame into PostgreSQL via SQLAlchemy/psycopg2, replacing the customer table on each run.
4.2 Database Layer
●	Engine: PostgreSQL
●	Database: customer_behavior
●	Table: customer (schema public)
●	Load strategy: full replace (if_exists="replace") — the pipeline is not currently incremental.

7. Known Issues & Recommendations
●	Naming defect: purchage_amount is a typo for purchase_amount, propagated from the notebook into all SQL queries and the Power BI model.
●	Hard-coded credentials: Database username/password are written directly in the notebook — a security risk for any shared or production version.
●	Full-refresh loading: the customer table is replaced entirely on every run; there is no incremental or historical load, so trend tracking across refreshes is not currently possible.
●	Empty scratch notebook: Untitled.ipynb contains no code and is assumed to be an unused placeholder.
●	Single data source: all analysis is based on a static CSV extract, not a live or recurring feed.
8. Success Metrics
●	All 10 SQL business questions return correct, non-null results against the loaded customer table.
●	Dashboard loads and refreshes successfully from the PostgreSQL source with no broken visuals.
●	Zero missing values remain in review_rating after the cleaning step.
●	Slicers correctly filter all KPIs and charts on the dashboard page.
